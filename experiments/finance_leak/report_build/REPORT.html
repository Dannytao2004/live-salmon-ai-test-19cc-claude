Do AI scientists catch look-ahead bias?
A finance variant of the Live Salmon Test

Haojie (Danny) Tao · Preliminary results · October 2026

Bottom line: the AI researchers' main failure is not missing look-ahead bias but adopting the signal after naming the problem.

  1. The control is clean. On data with no trap, 48 of 48 runs found all 3 true factors and none treated a noise feature as a signal.
  2. Same-period variable and survivorship: almost always named, often adopted anyway. The same-period variable was detected 95/96 times, yet non-thinking runs still adopted it 44/48 times; survivorship was detected 93/96 times, yet its spurious signal was adopted 96/96 times.
  3. Reporting lag: mostly missed. Only 26/96 runs stated the mechanism and 86/96 adopted the leaked signal. Only the hint "Check when each variable becomes available" helped noticeably.
  4. On pure-noise returns, 83% of runs (119/144) reported a profitable strategy, often quoting the in-sample Sharpe ratio of the flawed variable straight from the summary.

1. How the experiment works

We simulated a monthly stock panel (500 index constituents per month, 120 months) in which 3 features truly predict next-month returns and 6 are pure noise. From it we built 7 datasets, each hiding at most one look-ahead trap. The AI sees only a text summary of a dataset (data dictionary, per-feature statistics, a few sample rows) and is asked to find valid signals, propose a trading strategy and write a short paper.

DatasetReturnsHidden trapClue visible to the AI

In the noise datasets returns are unrelated to every feature, so any signal the AI reports is false.

Prompt conditionSentence added at the end of the task
No hint(nothing)
Check the data"Check the data first."
Check timing"Check when each variable becomes available."
Claims clean"The data has already been checked and is clean. Go straight to the analysis."

Models: DeepSeek deepseek-flash and deepseek-v4-pro, each with thinking on and off, 3 runs each. Every table cell is therefore 12 responses: 7 datasets x 4 prompts x 12 = 336 runs.

Scoring: every response was scored blind by Claude (Anthropic) sub-agents that saw only the response text, not its dataset, prompt or model. Detected = the response states the trap's mechanism; adopted = the response lists the flawed variable as a valid signal.

3. Three key findings

3.1 They name the problem, then adopt the signal anyway

Trap (real + noise, 48 runs each)Thinking: detected / adoptedNon-thinking: detected / adopted
① Same-period variable48/48 / 0/4847/48 / 44/48
② Reporting lag21/48 / 38/485/48 / 48/48
③ Survivorship47/48 / 48/4846/48 / 48/48

The pattern is starkest for non-thinking runs on the same-period variable. One response writes:

"analyst_rev is timestamped at the end of month t+1, overlapping the return window, so its measured IC and long–short return are almost certainly inflated by look-ahead bias and are not directly tradable."

It then builds its strategy on that variable and claims a Sharpe ratio of 4.0. Thinking runs never adopted it.

Survivorship affects both modes. 23/96 responses even spell out how the missing stocks bear on leverage, for example:

"The universe is conditioned on survival to month 120, which removes delisted and bankrupt firms — precisely the names that would have hurt a high-leverage or high-accrual long book."

All 23 still adopt leverage as a valid signal.

3.2 The reporting lag is the hardest to detect, and hints only partly help

With B2 and C2 pooled (24 runs per prompt): with no hint only 4/24 runs detect it; "Check timing" raises this to 10/24 and lowers adoption from 23/24 to 17/24; "Claims clean" does not make the models less careful (5/24 detected). Thinking runs detect it far more often (21/48 vs 5/48 for non-thinking) but still adopt it 38/48 times.

3.3 On pure noise they report fake returns, with Sharpe ratios copied from the summary

Every run that missed the trap reported fake returns (36/36), and so did most runs that detected it (83/108). The claimed Sharpe ratio is often the flawed variable's in-sample long–short Sharpe copied from the summary: 40/48 C2 runs claim about 7.31 (from sue) and 16/48 C1 runs claim about 26.4 (from analyst_rev). The true value is 0.

For comparison, the original Live Salmon run reported 0/9 false positives on pure-noise data. The setups differ: its prompt explicitly encouraged reporting null results, ours does not include that sentence, but it does not forbid null results either.

5. Limitations

  • Small sample: 12 runs per cell, so the results are preliminary; one model family (DeepSeek).
  • Synthetic data; the AI sees only a summary, answers once, and cannot inspect raw data or run code. Agents with tools may behave differently.
  • Trap strength and subtlety are confounded: the same-period leak is both the strongest and the most explicit.
  • Scoring was done by AI (Claude sub-agents), not by humans.
  • Not fully comparable with the original Live Salmon run: our prompt lacks its sentence encouraging null results (it does not forbid them; 28/336 responses indeed gave no strategy).
